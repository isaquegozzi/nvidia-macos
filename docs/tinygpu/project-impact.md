# TinyGPU — impacto no projeto (TG0, somente .md)

> Fase TG0. Nenhum hardware tocado, nenhum código alterado. Este doc classifica artefatos pré-TinyGPU à luz de ADR-0002 (estratégia C — TinyGPU-compatible transport).
> Escala: `STILL_REQUIRED` = ainda necessário no caminho crítico; `USEFUL_REFERENCE` = não executa, mas corrobora/previne erro; `REPLACED_BY_TINYGRAD` = o stack tinygrad assume a função; `DEFERRED` = fora do caminho crítico MAC-COMPUTE-0, reativar sob condição.
> `docs/README.md` não editado (índice com o coordenador).

## 2. Metal segue NÃO resolvido por esta descoberta (1 parágrafo)

A descoberta TinyGPU fecha no máximo o transporte PCI + bring-up compute userspace (BARs/CFG/MMIO/sysmem via dext e kernels via GSP/GPFIFO/QMD com compiler Docker), mas não entrega nada da pilha gráfica macOS — `IOGPUFamily`/`IOAcceleratorFamily2`/`IOGraphics`/`WindowServer`/Metal, `library-validation`, assinatura de driver user-space pelo mesmo Team ID, nem display/modeset/KMS (teto demonstrado nos dois entrypoints é compute-only sem display vs framebuffer patch legado — gate §4, why-usb4 F UNCERTAIN, binary-architecture dext mínimo só com `PCIDriverKit/DriverKit`) — de modo que MAC-COMPUTE-0 (MEDIUM, ADR-0002 §3) não implica MAC-DISPLAY/Metal, que permanecem fora de escopo e sem caminho.
